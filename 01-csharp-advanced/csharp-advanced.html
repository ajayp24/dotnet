1 Delegates

A delegate is a type-safe, object-oriented function pointer. It holds a reference to a method (or chain of methods) matching a specific signature, and is the foundation for events, callbacks, LINQ, and async patterns.

Custom Delegate Declaration

C#
// Custom delegate declaration
public delegate int MathOperation(int x, int y);

public class DelegateBasics
{
    public static int Add(int x, int y) => x + y;
    public static int Multiply(int x, int y) => x * y;

    public static void Run()
    {
        MathOperation op = Add;
        Console.WriteLine(op(3, 4));   // 7

        op = Multiply;
        Console.WriteLine(op(3, 4));   // 12
    }
}

Built-in Generic Delegates: Func, Action, Predicate

Func<T, TResult>Returns a value. Last type parameter is the return type. Up to 16 input parameters.
Action<T>Returns void. Zero to 16 input parameters. For side-effect operations.
Predicate<T>Returns bool. Equivalent to Func<T, bool>. Used for filtering/matching.
C#
public static void BuiltInDelegates()
{
    // Func<TInput, TOutput> — returns a value
    Func<string, int> getLength = s => s.Length;
    Console.WriteLine(getLength("hello"));   // 5

    // Func with multiple inputs
    Func<int, int, int> add = (a, b) => a + b;
    Console.WriteLine(add(10, 20));           // 30

    // Action<T> — returns void
    Action<string> log = msg => Console.WriteLine($"[LOG] {msg}");
    log("Server started");

    // Predicate<T> — returns bool
    Predicate<int> isEven = n => n % 2 == 0;
    Console.WriteLine(isEven(4));  // True
    Console.WriteLine(isEven(7));  // False
}

Multicast Delegates

A multicast delegate holds references to multiple methods. Invocation calls each in order. The return value is from the last method in the chain.

C#
public delegate void Notify(string message);

public static void MulticastDemo()
{
    Notify notify = EmailNotify;
    notify += SmsNotify;
    notify += SlackNotify;

    notify("Order #1042 shipped!");
    // Email: Order #1042 shipped!
    // SMS:   Order #1042 shipped!
    // Slack: Order #1042 shipped!

    notify -= SmsNotify;   // remove one handler

    // Inspect the invocation list
    foreach (var handler in notify.GetInvocationList())
        Console.WriteLine($"Handler: {handler.Method.Name}");
}

Real Example: Plugin Pipeline

C#
public class PluginPipeline
{
    public delegate string PipelineStep(string input);
    private PipelineStep _pipeline;

    public PluginPipeline AddStep(PipelineStep step)
    {
        _pipeline += step;
        return this;
    }

    public string Execute(string input)
    {
        string result = input;
        foreach (var step in _pipeline.GetInvocationList())
            result = ((PipelineStep)step)(result);
        return result;
    }
}

// Usage:
var pipeline = new PluginPipeline()
    .AddStep(s => s.Trim())
    .AddStep(s => s.ToUpper())
    .AddStep(s => $"[PROCESSED] {s}");

Console.WriteLine(pipeline.Execute("  hello world  "));
// [PROCESSED] HELLO WORLD
Interview Q&A

Q: When would you use a delegate instead of an interface for callbacks?

A: Use a delegate when the callback is a single method, you want multicast (notify multiple subscribers), or you're composing behavior at runtime. Use an interface when the callback involves multiple related methods, you need DI container support, or the implementer must carry state. Rule of thumb: one method → delegate. Object with behavior → interface.

2 Events

Events are multicast delegate fields with restricted access. External code can only subscribe (+=) or unsubscribe (-=); only the declaring class can invoke them.

C#
public class OrderPlacedEventArgs : EventArgs
{
    public int      OrderId   { get; init; }
    public decimal  Amount    { get; init; }
    public DateTime PlacedAt  { get; init; }
}

public class OrderService
{
    // event keyword — external code cannot invoke or reassign
    public event EventHandler<OrderPlacedEventArgs>? OrderPlaced;

    public void PlaceOrder(int orderId, decimal amount)
    {
        Console.WriteLine($"Order {orderId} placed for ${amount}");

        // Thread-safe raise with null-conditional operator
        OrderPlaced?.Invoke(this, new OrderPlacedEventArgs
        {
            OrderId  = orderId,
            Amount   = amount,
            PlacedAt = DateTime.UtcNow
        });
    }
}

// Subscriber
public class EmailService
{
    public void OnOrderPlaced(object? sender, OrderPlacedEventArgs e)
        => Console.WriteLine($"[Email] Confirmation for order {e.OrderId}");
}

// Wire up:
var orders = new OrderService();
var email  = new EmailService();
orders.OrderPlaced += email.OnOrderPlaced;
orders.PlaceOrder(1042, 299.99m);

Why events over public delegates?

BAD — Public Delegate Field

  • External code can assign null (wiping all subscribers)
  • External code can invoke directly
  • No encapsulation of who controls firing

GOOD — event Keyword

  • External code: only += and -= allowed
  • Only the declaring class can invoke
  • Clear contract: publisher controls timing
Pitfall — Memory Leak

If a short-lived subscriber subscribes to a long-lived publisher's event and never unsubscribes, the publisher holds a reference preventing garbage collection. This is one of the most common C# memory leaks.

C#
// GOOD: implement IDisposable to unsubscribe
public class ProperSubscriber : IDisposable
{
    private readonly Publisher _publisher;
    private bool _disposed;

    public ProperSubscriber(Publisher publisher)
    {
        _publisher = publisher;
        _publisher.Tick += OnTick;   // subscribe
    }

    private void OnTick(object? sender, EventArgs e)
        => Console.WriteLine("Tick");

    public void Dispose()
    {
        if (!_disposed)
        {
            _publisher.Tick -= OnTick;  // unsubscribe!
            _disposed = true;
        }
    }
}
Tip

Use WeakReference or WeakEventManager (WPF) when you cannot control the subscriber's lifetime. In modern code, prefer IDisposable + using to ensure cleanup.

3 Lambda Expressions

A lambda is an anonymous function that can capture variables from its enclosing scope — this is called a closure.

C#
// Expression lambda (implicit return)
Func<int, int> square = x => x * x;

// Statement lambda (block body)
Func<int, int, int> max = (a, b) =>
{
    if (a > b) return a;
    return b;
};

// Closure: capturing local variable
int multiplier = 3;
Func<int, int> times = n => n * multiplier;  // captures 'multiplier'

Console.WriteLine(times(4));  // 12
multiplier = 10;               // change the captured variable
Console.WriteLine(times(4));  // 40 — reflects the mutation!

LINQ Queries with Lambdas

C#
var inStockElectronics = products
    .Where(p => p.InStock && p.Category == "Electronics")
    .OrderByDescending(p => p.Price)
    .Select(p => new { p.Name, p.Price })
    .ToList();

// Aggregate
decimal total = products
    .Where(p => p.InStock)
    .Sum(p => p.Price);

// GroupBy
var byCategory = products
    .GroupBy(p => p.Category)
    .Select(g => new
    {
        Category     = g.Key,
        Count        = g.Count(),
        AveragePrice = g.Average(p => p.Price)
    });

Pitfall: Closure Capturing Loop Variable

Pitfall

In a for loop, all lambdas share the same captured variable. By the time the lambdas execute, the loop has completed and i holds its final value.

C#
// BUG: all lambdas capture the SAME 'i' variable
var actions = new List<Action>();
for (int i = 0; i < 5; i++)
    actions.Add(() => Console.WriteLine(i));

actions.ForEach(a => a());  // Prints: 5 5 5 5 5

// FIX: capture a local copy per iteration
var fixed_actions = new List<Action>();
for (int i = 0; i < 5; i++)
{
    int captured = i;   // new variable each iteration
    fixed_actions.Add(() => Console.WriteLine(captured));
}
fixed_actions.ForEach(a => a());  // Prints: 0 1 2 3 4

// NOTE: foreach (C# 5+) already creates a fresh variable per iteration — safe!

4 Expression Trees

Func<T>Expression<Func<T>>
TypeCompiled delegate (IL)Data structure (AST)
Can invoke directlyYesNo — must .Compile() first
Can inspect/traverseNoYes
Used byIn-memory operationsEF Core, dynamic query builders
C#
using System.Linq.Expressions;

// Func — compiled, can run but cannot inspect
Func<int, bool> func = x => x > 0;
func(5);  // True

// Expression — data structure representing the lambda
Expression<Func<int, bool>> expr = x => x > 0;

// Inspect the AST
var binary = (BinaryExpression)expr.Body;
Console.WriteLine(binary.Left);    // x
Console.WriteLine(binary.Right);   // 0
Console.WriteLine(binary.NodeType); // GreaterThan

// Compile to delegate and invoke
Func<int, bool> compiled = expr.Compile();
compiled(5);   // True
compiled(-3);  // False

How EF Core Uses Expression Trees

C#
// EF Core: expression tree is TRANSLATED to SQL — never runs in C#
var users = await dbContext.Users
    .Where(u => u.IsActive && u.Age > 18)  // Expression<Func<User, bool>>
    .ToListAsync();
// Generated SQL: SELECT * FROM Users WHERE IsActive = 1 AND Age > 18

// In-memory list: Func runs in C# (no SQL)
var filtered = inMemoryList
    .Where(u => u.IsActive && u.Age > 18)  // Func<User, bool>
    .ToList();

Real Example: Dynamic Query Filter Builder

C#
using System.Linq.Expressions;

public static class DynamicQueryBuilder
{
    // Builds: entity => entity.PropertyName == value
    public static Expression<Func<T, bool>> BuildEqualityFilter<T>(
        string propertyName, object value)
    {
        var parameter = Expression.Parameter(typeof(T), "entity");
        var property  = Expression.Property(parameter, propertyName);
        var constant  = Expression.Constant(
            Convert.ChangeType(value, property.Type));
        var equality  = Expression.Equal(property, constant);

        return Expression.Lambda<Func<T, bool>>(equality, parameter);
    }

    // Combine two filters with AND
    public static Expression<Func<T, bool>> And<T>(
        Expression<Func<T, bool>> left,
        Expression<Func<T, bool>> right)
    {
        var param     = left.Parameters[0];
        var rightBody = new ParameterReplacer(right.Parameters[0], param)
            .Visit(right.Body);
        var combined  = Expression.AndAlso(left.Body, rightBody);
        return Expression.Lambda<Func<T, bool>>(combined, param);
    }
}

// Usage:
var deptFilter   = DynamicQueryBuilder.BuildEqualityFilter<Employee>("Department", "Engineering");
var activeFilter = DynamicQueryBuilder.BuildEqualityFilter<Employee>("IsActive", true);
var combined     = DynamicQueryBuilder.And(deptFilter, activeFilter);

var result = employees.AsQueryable().Where(combined).ToList();
Tip

Expression trees are the key to writing generic repository query builders that work with EF Core. You cannot use out/ref parameters or await inside an expression tree — these are compile-time errors.

5 LINQ — Deferred vs Immediate Execution

Deferred Operators

  • Where, Select, SelectMany
  • OrderBy, ThenBy, OrderByDescending
  • GroupBy, Join, GroupJoin
  • Take, Skip, TakeWhile, SkipWhile
  • Distinct, Union, Intersect, Except

Immediate Operators

  • ToList(), ToArray(), ToDictionary()
  • Count(), LongCount()
  • First(), FirstOrDefault()
  • Single(), SingleOrDefault()
  • Sum(), Min(), Max(), Average()
  • Any(), All(), Contains()
C#
private static IEnumerable<int> GetNumbers()
{
    Console.WriteLine("  [DB Query Executed]");
    for (int i = 1; i <= 5; i++)
        yield return i;
}

public static void DeferredDemo()
{
    // DEFERRED: no execution here — just builds a pipeline
    IEnumerable<int> query = GetNumbers().Where(n => n % 2 == 0);

    Console.WriteLine("Query defined. No execution yet.");

    // Executes NOW (first enumeration)
    foreach (int n in query) Console.WriteLine(n);

    // Executes AGAIN (second enumeration — query re-runs!)
    foreach (int n in query) Console.WriteLine(n);

    // FIX: materialize once
    List<int> list = GetNumbers().Where(n => n % 2 == 0).ToList();
    // Executes ONCE; subsequent iterations use the in-memory list
}

Real Example: Multiple Enumerations Problem

Pitfall — Silent Performance Bug

Enumerating an IEnumerable<T> multiple times re-runs the underlying query each time. When that query is a database call or expensive computation, this is a serious performance issue that often goes unnoticed.

C#
// BAD: IEnumerable returned — each call re-hits the data source
IEnumerable<string> users = FetchFromDatabase();

Console.WriteLine(users.Count());   // [DB Query Executed]
Console.WriteLine(users.First());   // [DB Query Executed]
foreach (var u in users) { }          // [DB Query Executed]

// GOOD: materialize once
List<string> userList = FetchFromDatabase().ToList(); // Executes once

Console.WriteLine(userList.Count);   // in-memory, no re-query
Console.WriteLine(userList[0]);      // in-memory
foreach (var u in userList) { }      // in-memory

IQueryable vs IEnumerable

C#
// IQueryable — server-side; generates SQL
IQueryable<Order> dbQuery = dbContext.Orders
    .Where(o => o.Amount > 100)        // → SQL WHERE
    .OrderBy(o => o.CreatedDate);      // → SQL ORDER BY
// ONE query executed when materialized

// IEnumerable — client-side; runs in C# after loading all rows!
IEnumerable<Order> memQuery = dbContext.Orders
    .AsEnumerable()                    // ← loads EVERYTHING into memory first!
    .Where(o => o.Amount > 100);      // filter runs in C#
Interview Q&A

Q: When does a LINQ query actually execute?

A: A LINQ query executes when: (1) you call an immediate operator such as ToList(), Count(), First(), Sum(), etc.; (2) you enumerate the result with foreach; or (3) you call GetEnumerator() / MoveNext() manually. Until then, the query is just a delegate chain (or expression tree for IQueryable) stored as a data structure — no data is accessed.

6 Extension Methods

Extension methods allow you to add methods to existing types without modifying them or subclassing. They must be in a static class, be static methods, and use this on the first parameter.

C#
public static class StringExtensions
{
    public static bool IsNullOrEmpty(this string? value)
        => string.IsNullOrEmpty(value);

    public static string ToTitleCase(this string value)
    {
        if (string.IsNullOrWhiteSpace(value)) return value;
        return string.Join(' ', value.Split(' ')
            .Select(w => w.Length > 0
                ? char.ToUpper(w[0]) + w.Substring(1).ToLower()
                : w));
    }

    public static string Truncate(this string value, int maxLength, string suffix = "...")
        => value.Length <= maxLength
            ? value
            : value.Substring(0, maxLength - suffix.Length) + suffix;
}

// Usage — looks like instance method calls:
"john doe".ToTitleCase();      // "John Doe"
"hello world".Truncate(8);    // "hello..."
((string?)null).IsNullOrEmpty(); // true — extension method handles null!

IEnumerable Extensions

C#
public static class EnumerableExtensions
{
    // Split items into fixed-size batches
    public static IEnumerable<IEnumerable<T>> Batch<T>(
        this IEnumerable<T> source, int batchSize)
    {
        var batch = new List<T>(batchSize);
        foreach (var item in source)
        {
            batch.Add(item);
            if (batch.Count == batchSize)
            {
                yield return batch;
                batch = new List<T>(batchSize);
            }
        }
        if (batch.Count > 0) yield return batch;
    }

    // Null-safe check
    public static bool HasItems<T>(this IEnumerable<T>? source)
        => source?.Any() == true;
}

Limitations

Pitfall — What Extension Methods Cannot Do

Cannot override instance methods: if the type already has a matching method, the instance method always wins — your extension is never called.

Cannot access private members: they are resolved as static calls; no special access to internals.

Compile-time resolution: extension methods do not participate in virtual dispatch or runtime polymorphism.

Null receiver allowed: unlike instance methods, extension methods can be called on null — the this parameter receives null without throwing NullReferenceException.

C#
// Generic method with constraints
public static T Max<T>(T a, T b) where T : IComparable<T>
    => a.CompareTo(b) >= 0 ? a : b;

// Requires new() and class
public static T CreateDefault<T>() where T : class, new()
    => new T();

// Multiple type parameters
public static Dictionary<TKey, TValue> Zip<TKey, TValue>(
    IEnumerable<TKey> keys,
    IEnumerable<TValue> values)
    where TKey : notnull
{
    return keys.Zip(values, (k, v) => new { k, v })
               .ToDictionary(x => x.k, x => x.v);
}

Generic Repository Pattern

C#
public interface IRepository<T, TId> where T : class
{
    Task<T?>              GetByIdAsync(TId id);
    Task<IEnumerable<T>>  GetAllAsync();
    Task<IEnumerable<T>>  FindAsync(Expression<Func<T, bool>> predicate);
    Task<T>               AddAsync(T entity);
    Task                  UpdateAsync(T entity);
    Task                  DeleteAsync(TId id);
}

public abstract class RepositoryBase<T, TId> : IRepository<T, TId>
    where T : class
{
    protected readonly DbContext Context;
    protected readonly DbSet<T> DbSet;

    protected RepositoryBase(DbContext context)
    {
        Context = context;
        DbSet   = context.Set<T>();
    }

    public virtual async Task<T?> GetByIdAsync(TId id)
        => await DbSet.FindAsync(id);

    public virtual async Task<IEnumerable<T>> FindAsync(
        Expression<Func<T, bool>> predicate)
        => await DbSet.Where(predicate).ToListAsync();

    // ... other default implementations
}

Covariance (out) and Contravariance (in)

C#
// COVARIANCE (out T) — can use a more derived type (read-only producers)
// IEnumerable<out T> is covariant
IEnumerable<string> strings = new List<string> { "hello" };
IEnumerable<object> objects = strings;  // works! string IS-A object

// CONTRAVARIANCE (in T) — can use a less derived type (write-only consumers)
// Action<in T> is contravariant
Action<object> objectAction = o => Console.WriteLine(o);
Action<string> stringAction = objectAction;  // works!
stringAction("hello");  // string passed, used as object internally

// Custom covariant interface (can only return T)
public interface IProducer<out T> { T Produce(); }

// Custom contravariant interface (can only accept T)
public interface IConsumer<in T> { void Consume(T item); }
Interview Q&A

Q: Why use generics instead of object?

A: Three reasons: (1) Type safety — compile-time checks catch errors; with object you get InvalidCastException at runtime. (2) Performance — generics avoid boxing/unboxing for value types; List<int> stores actual ints on the heap contiguously, while List<object> boxes every int to a separately allocated object. (3) Readability — List<Order> communicates intent clearly and eliminates casting everywhere.

8 Reflection

Reflection allows you to inspect and interact with types, methods, properties, and attributes at runtime — without knowing them at compile time.

C#
using System.Reflection;

Type type = typeof(Person);

// Properties
foreach (var prop in type.GetProperties(
    BindingFlags.Public | BindingFlags.Instance))
{
    Console.WriteLine($"{prop.PropertyType.Name} {prop.Name}");
}

// Invoke method dynamically
var person    = new Person("Alice", 30);
var greetMeth = type.GetMethod("Greet");
var result    = greetMeth?.Invoke(person, new object[] { "Hello" });
Console.WriteLine(result);  // Hello, I'm Alice, age 30

// Get/Set property
var nameProp = type.GetProperty("Name");
nameProp?.SetValue(person, "Bob");

// Access private field
var secret = type.GetField("_secret",
    BindingFlags.NonPublic | BindingFlags.Instance);
Console.WriteLine(secret?.GetValue(person));

Real Example: Attribute-Based Validator

C#
public static class ModelValidator
{
    public static IReadOnlyList<string> Validate(object model)
    {
        var errors = new List<string>();
        var type   = model.GetType();

        foreach (var prop in type.GetProperties())
        {
            var value   = prop.GetValue(model);
            var context = new ValidationContext(model) { MemberName = prop.Name };

            foreach (var attr in prop.GetCustomAttributes<ValidationAttribute>())
            {
                var result = attr.GetValidationResult(value, context);
                if (result != ValidationResult.Success && result is not null)
                    errors.Add(result.ErrorMessage ?? "Validation failed");
            }
        }
        return errors;
    }
}

// Model decorated with validation attributes
public class ProductCreateRequest
{
    [Required(ErrorMessage = "Name is required")]
    [StringLength(100, MinimumLength = 2)]
    public string Name { get; set; } = "";

    [Range(0.01, 99999.99)]
    public decimal Price { get; set; }
}

Performance and Alternatives

Pitfall — Reflection is Slow

Direct call: ~1 ns. Compiled expression delegate: ~2 ns. MethodInfo.Invoke: ~100–500 ns. Never use raw reflection on a hot path.

C#
// Strategy 1: cache MethodInfo (marginal improvement)
private static readonly MethodInfo? _method =
    typeof(string).GetMethod("ToUpper", Type.EmptyTypes);

// Strategy 2: compile to delegate ONCE — near-direct-call speed (~2ns)
private static readonly Func<string, string> _toUpper;

static MyClass()
{
    var param  = Expression.Parameter(typeof(string), "s");
    var method = typeof(string).GetMethod("ToUpper", Type.EmptyTypes)!;
    var call   = Expression.Call(param, method);
    _toUpper   = Expression.Lambda<Func<string, string>>(call, param).Compile();
}

9 Dynamic

dynamic vs var vs object

KeywordType ResolutionIntelliSenseNull SafetyPerformance

C#
// var — compile-time type inference (still strongly typed)
var name = "Alice";           // type is string
// name.FakeMethod();          // compile error

// object — any type assignable, but must cast to use members
object obj = "Alice";
// obj.ToUpper();              // compile error
((string)obj).ToUpper();     // cast required

// dynamic — DLR resolves members at RUNTIME
dynamic dyn = "Alice";
Console.WriteLine(dyn.ToUpper());  // OK — runtime dispatch
Console.WriteLine(dyn.Length);       // OK

dyn = 42;   // can reassign to completely different type
Console.WriteLine(dyn + 8);   // 50

ExpandoObject — Runtime Property Bags

C#
using System.Dynamic;

dynamic person = new ExpandoObject();
person.Name  = "Alice";
person.Age   = 30;
person.Greet = (Func<string>)(() => $"Hi, I'm {person.Name}");

Console.WriteLine(person.Greet());  // Hi, I'm Alice

// Iterate as dictionary
var dict = (IDictionary<string, object?>)person;
foreach (var kvp in dict)
    Console.WriteLine($"{kvp.Key}: {kvp.Value}");
Pitfall

dynamic trades compile-time safety for flexibility. Typos become RuntimeBinderException errors discovered only at runtime. There is no refactoring support and no IntelliSense for dynamic members.

Interview Q&A

Q: When would you actually use dynamic in production?

A: Rarely — only when you have no static type information: (1) COM interop — Office automation, legacy COM objects. dynamic is the canonical C# solution here. (2) Dynamic language interop — scripting hosts calling into IronPython/IronRuby. (3) Schema-less data — truly unknown property shapes (though Dictionary<string, object> or JsonNode is safer and faster). Avoid dynamic everywhere else — use interfaces, generics, or expression trees to maintain type safety.
