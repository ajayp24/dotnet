1. Task vs Thread

Thread — OS-Level Primitive

A Thread is an OS-level construct. Each thread gets its own stack (default 1 MB on Windows), is scheduled by the OS kernel, and is expensive to create and destroy. Creating thousands of threads is not feasible.

csharp
// Creating a Thread explicitly
var thread = new Thread(() =>
{
    Console.WriteLine($"Running on Thread ID: {Thread.CurrentThread.ManagedThreadId}");
    Thread.Sleep(1000); // Blocks the entire OS thread
});
thread.IsBackground = true;
thread.Start();
thread.Join(); // Caller blocks until thread completes

Task — Logical Unit of Work on ThreadPool

A Task is a higher-level abstraction representing work that may run asynchronously. Task.Run schedules work on the ThreadPool, which reuses threads instead of creating new ones.

csharp
// Task.Run — uses ThreadPool (reuses existing threads)
var task = Task.Run(() =>
{
    Console.WriteLine($"Thread ID: {Thread.CurrentThread.ManagedThreadId}");
    return ComputePrimes(1_000_000);
});
int result = await task; // Awaiting does NOT block the calling thread

// I/O: Don't use Thread or Task.Run — just async/await directly
public async Task<string> FetchDataAsync(string url)
{
    // During await, NO thread is consumed — OS handles I/O completion
    return await new HttpClient().GetStringAsync(url);
}

// CPU work: offload to ThreadPool, freeing ASP.NET request thread
public async Task<int> ComputeOnThreadPool()
{
    return await Task.Run(() => ComputePrimes(10_000_000));
}

Interview Q

Q: "Why does async/await not create a new thread?"

async/await is a compiler transformation, not a threading construct. When you await an I/O operation, the .NET runtime registers a callback with the OS I/O completion port. The thread is released back to the ThreadPool immediately. When I/O completes, the OS signals completion and the continuation is posted back to the ThreadPool (or SynchronizationContext). No thread sits blocked waiting. For CPU work, a thread is still needed (Task.Run), but await ensures the calling thread is not blocked while waiting for the result.

2. async/await Internals

The Compiler-Generated State Machine

When you write an async method, the C# compiler generates a state machine struct that implements IAsyncStateMachine. Each await point becomes a state. The MoveNext() method is called to resume execution after each await.

csharp
// What you write:
public async Task<string> FetchDataAsync(string url)
{
    Console.WriteLine("Before await");
    var result = await new HttpClient().GetStringAsync(url);
    Console.WriteLine("After await");
    return result.ToUpper();
}

// Simplified compiler output (conceptually):
[CompilerGenerated]
private struct FetchDataAsyncStateMachine : IAsyncStateMachine
{
    public int _state;   // -1 = not started, 0 = initial, 1 = after first await
    public AsyncTaskMethodBuilder<string> _builder;
    public string url;
    private TaskAwaiter<string> _awaiter;

    public void MoveNext()
    {
        string result;
        try
        {
            if (_state == 0)
            {
                Console.WriteLine("Before await");
                var task = new HttpClient().GetStringAsync(url);
                _awaiter = task.GetAwaiter();

                if (!_awaiter.IsCompleted)  // Not done yet — suspend
                {
                    _state = 1;
                    _builder.AwaitUnsafeOnCompleted(ref _awaiter, ref this);
                    return;  // Control returns to caller — NO THREAD BLOCKED
                }
            }
            // State 1: resumes here after I/O completes
            result = _awaiter.GetResult();
            Console.WriteLine("After await");
            _builder.SetResult(result.ToUpper());
        }
        catch (Exception ex) { _builder.SetException(ex); }
    }

    public void SetStateMachine(IAsyncStateMachine sm) { }
}

Task<T> vs ValueTask<T>

csharp
// Task<T> always allocates a heap object
public async Task<int> GetValueWithTask()
{
    await Task.Delay(100);
    return 42;
}

// ValueTask<T> — avoids allocation when result is available synchronously
// Use when the method FREQUENTLY completes without actually awaiting
public ValueTask<int> GetCachedValue(int key)
{
    if (_cache.TryGetValue(key, out int cached))
        return new ValueTask<int>(cached); // Synchronous path — ZERO allocation

    return new ValueTask<int>(FetchFromDatabaseAsync(key)); // Async path
}
ValueTask Rules

Can only be awaited once. Cannot be stored and awaited later. Do NOT call .Result on it. Best for: cache layers, synchronous fast paths in async interfaces, hot paths where allocations matter.

async void — The Danger Zone

csharp
// DANGEROUS: async void — exceptions are unhandled, fire-and-forget
public async void DangerousFireAndForget()
{

public static async Task SafeFireAndForget(

3. SynchronizationContext

What It Is

SynchronizationContext is an abstraction that captures "where" code should run when it returns after an await. It provides a Post() method to schedule work on a specific context — e.g., the UI thread or an ASP.NET request thread.

csharp
public async Task ExplainContextCapture()
{
    // await captures SynchronizationContext.Current HERE
    var capturedContext = SynchronizationContext.Current;

    Console.WriteLine($"Before await: Thread {Thread.CurrentThread.ManagedThreadId}, " +
                      $"Context: {capturedContext?.GetType().Name ?? "null"}");

    await Task.Delay(100);
    // After delay, runtime posts continuation back to capturedContext
    // WinForms: resumes on UI thread (WindowsFormsSynchronizationContext)
    // ASP.NET Core: resumes on any ThreadPool thread (context is null)

    Console.WriteLine($"After await: Thread {Thread.CurrentThread.ManagedThreadId}");
}

ASP.NET Core Has NO SynchronizationContext

csharp
[ApiController]
[Route("api/[controller]")]
public class DemoController : ControllerBase
{
    [HttpGet]
    public async Task<IActionResult> Get()
    {
        // SynchronizationContext.Current is always null in ASP.NET Core
        Console.WriteLine(SynchronizationContext.Current); // null

        await Task.Delay(100);

        // May run on a DIFFERENT ThreadPool thread — that's fine and by design
        Console.WriteLine(SynchronizationContext.Current); // still null

        return Ok("Done");
    }
}

WinForms / WPF — UI Thread Context

csharp
// WinForms: WindowsFormsSynchronizationContext is set automatically
private async void LoadButton_Click(object sender, EventArgs e)
{
    loadButton.Enabled = false;  // UI thread — safe

    // SynchronizationContext.Current = WindowsFormsSynchronizationContext
    var data = await FetchDataAsync(); // Suspends, releases UI thread

    // AUTOMATICALLY resumes on UI thread because of captured context
    resultLabel.Text = data;       // Safe: back on UI thread
    loadButton.Enabled = true;     // Safe: back on UI thread
}
Interview Q

Q: "What is SynchronizationContext and why does ASP.NET Core not have one?"

SynchronizationContext is a mechanism allowing continuations after await to be posted back to a specific execution context — most importantly, a specific thread. In WinForms/WPF, the UI framework provides a context that posts work back to the UI thread, necessary because only the UI thread can update controls.

ASP.NET Core deliberately has no SynchronizationContext. The team removed it because: (1) it was a source of deadlocks when mixing sync and async, (2) it imposed thread affinity that hurt scalability, and (3) HttpContext objects are safe to access from any thread under proper async patterns. Continuations run on any available ThreadPool thread, maximizing throughput.

4. ConfigureAwait(false)

What It Does

ConfigureAwait(false) tells the awaiter: "Do NOT capture the current SynchronizationContext. When the continuation runs, use any available ThreadPool thread."

csharp
// Without ConfigureAwait(false) — captures current SynchronizationContext
await SomeOperationAsync();
// Continuation tries to post back to UI thread / request context

// With ConfigureAwait(false) — ignores SynchronizationContext
await SomeOperationAsync().ConfigureAwait(false);
// Continuation runs on any ThreadPool thread — more efficient, avoids deadlock

// ===== LIBRARY CODE: always use ConfigureAwait(false) =====
public static async Task<string> FetchAsync(string url)
{
    using var client = new HttpClient();
    var response = await client.GetAsync(url).ConfigureAwait(false);
    var content = await response.Content.ReadAsStringAsync().ConfigureAwait(false);
    return content.ToUpper();
}

// ===== WinForms APPLICATION: do NOT use ConfigureAwait(false) =====
// if you need to update UI after the await
private async void LoadButton_Click(object sender, EventArgs e)
{
    var data = await FetchDataAsync();  // NO ConfigureAwait(false) — need UI thread
    label.Text = data;  // Must run on UI thread
}

The Deadlock ConfigureAwait(false) Prevents

csharp
// DEADLOCK SCENARIO (ASP.NET 4.x / WinForms):

private async Task<string> GetDataAsync()
{
    await Task.Delay(100); // Captures: "post continuation to UI thread"
    return "data";
}

// 1. UI thread calls GetDataDeadlock()
// 2. GetDataDeadlock() calls GetDataAsync() and BLOCKS with .Result
// 3. GetDataAsync awaits Task.Delay — captured context = UI thread
// 4. .Result BLOCKS the UI thread
// 5. Continuation scheduled to post back to UI thread (which is blocked)
// 6. DEADLOCK — thread waits for task, task waits for thread
public string GetDataDeadlock() => GetDataAsync().Result;  // NEVER DO THIS

// FIX: ConfigureAwait(false) in the async method
private async Task<string> GetDataAsyncSafe()
{
    await Task.Delay(100).ConfigureAwait(false); // Don't capture context
    return "data"; // Runs on ThreadPool — no deadlock
}
public string SafeSyncCall() => GetDataAsyncSafe().GetAwaiter().GetResult(); // OK

// BEST FIX: Async all the way
public async Task<string> GetDataCorrectly() => await GetDataAsync(); // No issue
Interview Q

Q: "What does ConfigureAwait(false) do?"

It configures the awaiter to NOT capture the current SynchronizationContext. Without it, when an awaited task completes, the continuation is scheduled back on the original context (e.g., UI thread). With ConfigureAwait(false), the continuation runs on any available ThreadPool thread. Benefits: (1) better performance — no context marshaling overhead, and (2) prevention of deadlocks when callers block synchronously with .Result or .Wait(). Library authors should always use it. In ASP.NET Core, it's effectively a no-op since there's no SynchronizationContext.

5. Deadlock in async/await

The Classic Deadlock — Step by Step

Deadlock Mechanism

1. Async method starts and hits an await. It captures the current SynchronizationContext and suspends.

2. The calling code blocks the thread with .Result, waiting for the Task to complete.

3. When the awaited operation finishes, the continuation is scheduled to run on the captured context — which requires the blocked thread.

4. Thread can't resume (blocked), Task can't complete (can't get thread) — DEADLOCK.

csharp
// ===== WRONG PATTERNS — deadlock in sync context =====

public string WrongPattern1() => GetDataAsync().Result;  // .Result — DEADLOCK

public void WrongPattern2()
{
    GetDataAsync().Wait();  // .Wait() — DEADLOCK
}

// GetAwaiter().GetResult() is slightly better (no AggregateException wrapping)
// but STILL DEADLOCKS if SynchronizationContext is present
public string WrongPattern3() => GetDataAsync().GetAwaiter().GetResult();

// ===== CORRECT PATTERNS =====

// Best: async all the way
public async Task<string> CorrectPattern1() => await GetDataAsync();

// Last resort for legacy code: Task.Run escapes the SynchronizationContext
public string LegacyFix()
{
    // Task.Run starts WITHOUT the current SynchronizationContext
    return Task.Run(() => GetDataAsync()).GetAwaiter().GetResult();
}

private async Task<string> GetDataAsync()
{
    await Task.Delay(100);
    return "result";
}
Interview Q

Q: "How can async/await cause a deadlock? Show me an example."

In WinForms or ASP.NET classic (not Core), if you call asyncMethod().Result: (1) the async method hits await and captures the SynchronizationContext, (2) .Result blocks the current thread, (3) when the awaited operation completes, the continuation tries to post back to the captured context, which requires the thread that is currently blocked by .Result, (4) deadlock. The fix is to make calling code async all the way up, or use ConfigureAwait(false) inside the async library method so it doesn't capture the context in the first place.

6. CancellationToken

CancellationTokenSource and CancellationToken

csharp
public async Task BasicCancellationExample()
{
    using var cts = new CancellationTokenSource();
    cts.CancelAfter(TimeSpan.FromSeconds(5)); // Auto-cancel after 5 seconds

    try
    {
        await DoLongWorkAsync(cts.Token);
    }
    catch (OperationCanceledException)
    {
        Console.WriteLine("Work was cancelled!");
    }
}

private async Task DoLongWorkAsync(CancellationToken ct)
{
    for (int i = 0; i < 100; i++)
    {
        ct.ThrowIfCancellationRequested(); // Throws OperationCanceledException

        await Task.Delay(100, ct); // Task.Delay respects cancellation too

        Console.WriteLine($"Step {i} complete");
    }
}

Real Example: Cancel HTTP Request (ASP.NET Core)

csharp
// ASP.NET Core passes HttpContext.RequestAborted automatically
// when the client disconnects, the CancellationToken is cancelled
[ApiController]
[Route("api/[controller]")]
public class SearchController : ControllerBase
{
    private readonly HttpClient _httpClient;

    [HttpGet]
    public async Task<IActionResult> Search(
        [FromQuery] string q,
        CancellationToken ct) // Bound to HttpContext.RequestAborted
    {
        var response = await _httpClient
            .GetAsync($"/api/search?q={Uri.EscapeDataString(q)}", ct)
            .ConfigureAwait(false);

        response.EnsureSuccessStatusCode();

        var results = await response.Content
            .ReadFromJsonAsync<string[]>(cancellationToken: ct)
            .ConfigureAwait(false);

        return Ok(results);
        // If client disconnects mid-request, OperationCanceledException is thrown
        // and the HTTP request is actually cancelled (not just the await)
    }
}

Linked Cancellation Tokens

csharp
// Cancel if EITHER user cancels OR timeout occurs
using var userCts = new CancellationTokenSource();
using var timeoutCts = new CancellationTokenSource(TimeSpan.FromSeconds(30));

// Cancels if ANY of the linked tokens is cancelled
using var linkedCts = CancellationTokenSource.CreateLinkedTokenSource(
    userCts.Token,
    timeoutCts.Token);

try
{
    await DoWorkAsync(linkedCts.Token);
}
catch (OperationCanceledException)
{
    if (timeoutCts.IsCancellationRequested)
        Console.WriteLine("Cancelled: timeout");
    else if (userCts.IsCancellationRequested)
        Console.WriteLine("Cancelled: user action");
}

Real Example: Background Service with Graceful Shutdown

csharp
public class BackgroundProcessor : BackgroundService
{
    private readonly ILogger<BackgroundProcessor> _logger;
    private readonly IMessageQueue _queue;

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        // stoppingToken is cancelled when app shuts down (Ctrl+C, SIGTERM, etc.)
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                var message = await _queue.DequeueAsync(stoppingToken);
                if (message != null)
                    await ProcessMessageAsync(message, stoppingToken);
            }
            catch (OperationCanceledException)
            {
                break; // Normal shutdown — don't log as error
            }
            catch (Exception ex)
            {
                _logger.LogError(ex, "Error processing message");
                await Task.Delay(1000, stoppingToken); // Wait before retry
            }
        }
    }

    private async Task ProcessMessageAsync(Message message, CancellationToken ct)
    {
        ct.ThrowIfCancellationRequested(); // Check at logical boundaries
        await StepOneAsync(message, ct);
        ct.ThrowIfCancellationRequested();
        await StepTwoAsync(message, ct);
    }
}

7. Task Parallel Library (TPL)

Task.WhenAll — Fan-Out Parallel Calls

csharp
// BAD: Sequential — total time = sum of all calls (~650ms)
public async Task<DashboardData> GetDashboardSequential()
{
    var users   = await GetUsersAsync();   // 200ms
    var orders  = await GetOrdersAsync();  // 300ms
    var metrics = await GetMetricsAsync(); // 150ms
    return new DashboardData(users, orders, metrics);
}

// GOOD: Parallel — total time = slowest call (~300ms)
public async Task<DashboardData> GetDashboardParallel(CancellationToken ct = default)
{
    // Fire all three requests simultaneously
    var usersTask   = GetUsersAsync(ct);
    var ordersTask  = GetOrdersAsync(ct);
    var metricsTask = GetMetricsAsync(ct);

    // Wait for ALL — throws first exception if any fails
    await Task.WhenAll(usersTask, ordersTask, metricsTask);

    return new DashboardData(
        await usersTask,   // Already complete — just get result
        await ordersTask,
        await metricsTask);
}

// Collecting ALL exceptions (not just first):
try { await Task.WhenAll(usersTask, ordersTask, metricsTask); }
catch
{
    var errors = new List<Exception>();
    if (usersTask.IsFaulted)   errors.Add(usersTask.Exception!.InnerException!);
    if (ordersTask.IsFaulted)  errors.Add(ordersTask.Exception!.InnerException!);
    if (metricsTask.IsFaulted) errors.Add(metricsTask.Exception!.InnerException!);
    throw new AggregateException("One or more API calls failed", errors);
}

Task.WhenAny — Timeout and Racing

csharp
// Pattern: Timeout using Task.WhenAny
public async Task<string?> FetchWithTimeoutAsync(
    string url,
    TimeSpan timeout,
    CancellationToken ct = default)
{
    var fetchTask   = _client.GetStringAsync(url, ct);
    var timeoutTask = Task.Delay(timeout, ct);

    var completedTask = await Task.WhenAny(fetchTask, timeoutTask);

    if (completedTask == timeoutTask)
    {
        Console.WriteLine("Request timed out!");
        return null; // Or: throw new TimeoutException()
    }

    return await fetchTask; // Re-await to propagate any exceptions
}

// Pattern: First successful result from multiple sources
public async Task<string> GetFromFastestSource(string[] urls, CancellationToken ct)
{
    var tasks = urls.Select(url => _client.GetStringAsync(url, ct)).ToList();

    while (tasks.Count > 0)
    {
        var first = await Task.WhenAny(tasks);
        tasks.Remove(first);
        try { return await first; } // Success
        catch { if (tasks.Count == 0) throw; } // Try remaining
    }
    throw new InvalidOperationException("All sources failed");
}

Throttled I/O with SemaphoreSlim

csharp
// WRONG: Parallel.ForEach with async lambda — async is "lost"
// Parallel.ForEach cannot await async lambdas — creates async void effectively
Parallel.ForEach(ids, async id =>  // async void lambda!
{
    await FetchItemAsync(id);  // Parallel.ForEach can't await this
});

// CORRECT: WhenAll + SemaphoreSlim for throttled I/O (max 10 concurrent)
public async Task ThrottledParallelIO(IEnumerable<int> ids, CancellationToken ct)
{
    using var semaphore = new SemaphoreSlim(10);

    var tasks = ids.Select(async id =>
    {
        await semaphore.WaitAsync(ct);
        try
        {
            return await FetchItemAsync(id, ct);
        }
        finally
        {
            semaphore.Release(); // Always release
        }
    });

    var results = await Task.WhenAll(tasks);
}
Pitfall: Over-Parallelizing I/O

Using Parallel.ForEach for I/O blocks ThreadPool threads waiting for async I/O completion. Under load, this causes ThreadPool starvation. Use Task.WhenAll with a SemaphoreSlim to limit concurrency while keeping threads free.

8. Thread Synchronization Primitives

lock Keyword (Monitor)

csharp
public class ThreadSafeCounter
{
    private int _count = 0;
    private readonly object _lock = new object();

    // lock compiles to Monitor.Enter / Monitor.Exit (in a try/finally)
    public void Increment()
    {
        lock (_lock) { _count++; }
    }

    public int Value
    {
        get { lock (_lock) { return _count; } }
    }

    // TryEnter — non-blocking attempt with timeout
    public bool TryIncrement()
    {
        if (Monitor.TryEnter(_lock, TimeSpan.FromMilliseconds(100)))
        {
            try { _count++; return true; }
            finally { Monitor.Exit(_lock); }
        }
        return false;
    }
}

SemaphoreSlim — Async Rate Limiter

csharp
public class RateLimitedApiClient
{
    private readonly SemaphoreSlim _semaphore;  // Max 5 concurrent calls
    private readonly HttpClient _httpClient;

    public RateLimitedApiClient(HttpClient httpClient)
    {
        _httpClient = httpClient;
        _semaphore = new SemaphoreSlim(initialCount: 5, maxCount: 5);
    }

    public async Task<string> CallApiAsync(string endpoint, CancellationToken ct = default)
    {
        await _semaphore.WaitAsync(ct);  // Async wait — doesn't block a thread
        try
        {
            return await _httpClient.GetStringAsync(endpoint, ct).ConfigureAwait(false);
        }
        finally
        {
            _semaphore.Release(); // Always release in finally
        }
    }
}

ReaderWriterLockSlim — Read-Heavy Scenarios

csharp
public class ThreadSafeCache<TKey, TValue> where TKey : notnull
{
    private readonly Dictionary<TKey, TValue> _cache = new();
    private readonly ReaderWriterLockSlim _rwLock = new();

    // Multiple readers can hold read lock simultaneously
    public bool TryGet(TKey key, out TValue? value)
    {
        _rwLock.EnterReadLock();
        try { return _cache.TryGetValue(key, out value); }
        finally { _rwLock.ExitReadLock(); }
    }

    // Exclusive write lock — all readers must finish first
    public void Set(TKey key, TValue value)
    {
        _rwLock.EnterWriteLock();
        try { _cache[key] = value; }
        finally { _rwLock.ExitWriteLock(); }
    }

    // GetOrAdd with double-check locking via upgradeable read lock
    public TValue GetOrAdd(TKey key, Func<TKey, TValue> factory)
    {
        _rwLock.EnterUpgradeableReadLock();
        try
        {
            if (_cache.TryGetValue(key, out var existing)) return existing;

            _rwLock.EnterWriteLock();
            try
            {
                if (!_cache.TryGetValue(key, out existing)) // Double-check
                    _cache[key] = existing = factory(key);
                return existing;
            }
            finally { _rwLock.ExitWriteLock(); }
        }
        finally { _rwLock.ExitUpgradeableReadLock(); }
    }
}

Interlocked — Lock-Free Atomic Operations

csharp
public class AtomicMetrics
{
    private long _requestCount = 0;

    // Atomic operations — no lock needed
    public long IncrementRequests() => Interlocked.Increment(ref _requestCount);
    public long DecrementRequests() => Interlocked.Decrement(ref _requestCount);
    public long GetCount()          => Interlocked.Read(ref _requestCount);
    public long Reset()             => Interlocked.Exchange(ref _requestCount, 0);

    // Compare-and-Swap — foundation of lock-free algorithms
    private int _activeConnections = 0;
    public bool TryAcquireConnection()
    {
        int current = _activeConnections;
        // If _activeConnections == current, set to current+1 and return current
        return Interlocked.CompareExchange(
            ref _activeConnections, current + 1, current) == current;
    }
}

9. Span<T>, Memory<T>, ReadOnlySpan<T>

What Is Span<T>?

Span<T> is a stack-allocated ref struct that provides a zero-overhead, type-safe view over contiguous memory — a managed array, a stack buffer, or unmanaged native memory. Slicing it causes zero allocation.

csharp
// Without Span: each Substring allocates a new string on the heap
string line = "2024-01-15,Alice,100.50";
string datePart = line.Substring(0, 10);  // Allocation!
string namePart = line.Substring(11, 5); // Allocation!

// With ReadOnlySpan: ZERO allocation — slices the original string in-place
ReadOnlySpan<char> span = line.AsSpan();
ReadOnlySpan<char> dateSpan = span[..10];  // No allocation
ReadOnlySpan<char> nameSpan = span[11..16]; // No allocation

Console.WriteLine(dateSpan.ToString()); // "2024-01-15"
Console.WriteLine(nameSpan.ToString()); // "Alice"

Parsing CSV Without Allocations

csharp
public static class CsvParser
{
    // Parses CSV line with zero intermediate allocations
    public static CsvRecord ParseLine(ReadOnlySpan<char> line)
    {
        int comma1 = line.IndexOf(',');
        ReadOnlySpan<char> dateSpan = line[..comma1];

        ReadOnlySpan<char> remaining = line[(comma1 + 1)..];
        int comma2 = remaining.IndexOf(',');
        ReadOnlySpan<char> nameSpan   = remaining[..comma2];
        ReadOnlySpan<char> amountSpan = remaining[(comma2 + 1)..];

        // Parse directly from span — no intermediate string allocation
        if (!DateOnly.TryParse(dateSpan, out var date))
            throw new FormatException($"Invalid date: {dateSpan.ToString()}");

        if (!decimal.TryParse(amountSpan, out var amount))
            throw new FormatException($"Invalid amount: {amountSpan.ToString()}");

        return new CsvRecord(date, nameSpan.ToString(), amount);
        // Only one allocation: the name string (unavoidable if storing it)
    }
}

record CsvRecord(DateOnly Date, string Name, decimal Amount);

{
    const int StackThreshold = 512;

        ? stackalloc byte[512]

        // Process...
    }
    finally
    {

    }
}

Interview Q

Q: "What is Span<T> and why use it?"

Span<T> is a stack-allocated ref struct that provides a zero-overhead, type-safe view over contiguous memory. It eliminates allocations in hot paths. Instead of string.Substring() (heap allocation), use AsSpan() for zero-copy slicing. Its ref struct restriction means it cannot be stored on the heap, in class fields, or across await points — use Memory<T> for those cases. Common uses: binary/text protocol parsing, buffer processing, avoiding new byte[] in I/O paths.

The Full Dispose Pattern

csharp
public class ResourceManager : IDisposable
{
    private FileStream? _fileStream;    // Managed resource
    private IntPtr _nativeHandle;       // Unmanaged resource
    private bool _disposed = false;

    // Called by user code: using statement or explicit Dispose()
    public void Dispose()
    {
        Dispose(disposing: true);
        GC.SuppressFinalize(this); // Tell GC not to call finalizer
    }

    // disposing = true: called by user (can access managed objects)
    // disposing = false: called by GC finalizer (managed objects may be collected)
    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;

        if (disposing)
        {
            // Free managed resources
            _fileStream?.Dispose();
            _fileStream = null;
        }

        // Free unmanaged resources (always, regardless of disposing flag)
        if (_nativeHandle != IntPtr.Zero)
        {
            FreeNativeResource(_nativeHandle);
            _nativeHandle = IntPtr.Zero;
        }

        _disposed = true;
    }

    // Safety net: called by GC if user forgot to call Dispose()
    ~ResourceManager() => Dispose(disposing: false);
}

IAsyncDisposable — Async Cleanup

csharp
public class AsyncDatabase : IAsyncDisposable
{
    private DbConnection? _connection;
    private bool _disposed = false;

    public async ValueTask DisposeAsync()
    {
        if (_disposed) return;
        _disposed = true;

        if (_connection != null)
        {
            await _connection.CloseAsync();     // Async: flushes pending ops
            await _connection.DisposeAsync();  // Async dispose
            _connection = null;
        }

        GC.SuppressFinalize(this);
    }
}

} // DisposeAsync() called automatically

// DbConnection SHOULD be disposed per operation
// Dispose() returns connection to ADO.NET pool — near-instantaneous
// Physical connection is NOT destroyed (unless pool is full)
public async Task<List<User>> GetUsersAsync(CancellationToken ct = default)
{
    await using var connection = new SqlConnection(_connectionString);
    await connection.OpenAsync(ct);

    await using var command = connection.CreateCommand();
    command.CommandText = "SELECT Id, Name, Email FROM Users";

    await using var reader = await command.ExecuteReaderAsync(ct);
    var users = new List<User>();

    while (await reader.ReadAsync(ct))
        users.Add(new User(reader.GetInt32(0), reader.GetString(1), reader.GetString(2)));

    return users;
    // connection.DisposeAsync() — returns to pool, NOT destroyed
}
